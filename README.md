# PS5 Turbo 0.4.2 — PS5 / PS4 / 模拟器兼容扩展测试版

支持 ×、○、□、△、L1、R1、L2、R2 分别选择连发，**每次启动插件，连发选键均恢复全部关闭**。
方向键、L3/R3、PS、Options、触摸板保留普通输入；L3+R3 也保留游戏原有功能。网页可独立勾选 L1+R1+十字键↓（下方向）与长按 L3+R3 两秒这两组快捷开关，默认仅启用前一组，网页保留总开关。

用户已在 PS5 13.60、WebKit 0.6.1 / y2jb、kstuff lite 环境中确认 v0.1 的 × 连发、松手停止和组合键开关正常。
用户随后反馈 0.2.6 当前使用正常，但这只代表用户测试过的游戏。**0.3.0 的 PS4 与模拟器扩展尚未在主机实测**；电脑端测试与编译不能证明全部游戏兼容。

## 0.4.2 精简设置页面

页面顶部仅保留“插件运行中”状态行，移除介绍与长说明，保留连发按键、开关、固定速度、快捷键和保存按钮。底部署名改为 `snkwz`。版本仍在浏览器标签标题、插件文件名与接口中提供，自动刷新与接替逻辑不变。

## 0.4.1 自动接替与升级清理

启动新版 ELF 时先检查进程访问与 kstuff，再通过旧版也支持的 STOP 标记请求其正常退出，最多等待 15 秒取得同一服务锁。不会按 `payload.elf` 名称杀进程，不强制终止未知 PID，不删除锁文件。新启动器之间由升级锁串行化。对于带版本记录的新版本，还会核对 PID 与进程启动时间，防止残留记录/PID 重用误判；可核实为相同或更高的运行版本不会被顶掉。固件未提供进程启动时间时，仍可通过锁和 STOP 接替，但不依赖不可验证的残留记录阻止接替。超时会明确记录失败，保留旧进程和旧文件。

新网页检测接口版本或会话变化后自动刷新；升级短暂断线后会继续重连。从 0.3.1 等旧网页首次切换至此版仍须手动刷新一次，以载入新的自动刷新代码。

成功启动网页和默认配置后，仅在 `/data/pldmgr/payloads/local/ps5-turbo/meta.json` 已指向本次新版文件、且新 ELF 身份校验通过时，清理同目录中已验证的更旧 Turbo ELF。不会清理其他目录、其他插件、较新文件、符号链接或无法确认的文件，也不改管理器元数据。导入新版应选“替换”，避免人为保留多个安装条目。

通过真实双进程交接、旧版无记录兼容、并发启动排他、同版/降级阻止、超时保留旧服务、PID 重用、网页自动刷新与清理边界测试；主机接替仍待实测。

## 0.4.0 固定 20 次/秒与手柄提示

连发速度固定为每秒 20 次（按下/松开各 25000 微秒），网页不再提供其他速度，配置/API 也拒绝其他值。每次启动清空选键，默认速度为 20 次/秒。

手柄快捷键恢复连发：两下短震（80ms + 60ms 间隔 + 80ms）；暂停连发：一下较长震动（180ms）。只作用于当前手柄，持续按住只提示一次。网页修改开关不主动震动。短暂分离线程发送提示，即使不再读取输入也会发送停止命令，不在游戏输入线程中等待提示结束。快速连续切换会合并为最新状态。

会记录游戏调用的震动值与模式，提示后尝试恢复最新已知值。只有已捕获到可恢复的模式时才临时切换模式 2；模式未知时仅使用游戏现有模式，以免永久改变原生触觉。部分 PS5 原生触觉模式可能不响应传统震动提示。接口无法解析或线程创建失败时连发开关仍有效，日志中的 `feedback`/`errors` 用于排查，不能证明实际震感。新增线程/回调需要主机验证，升级前须关闭游戏并停止旧插件（共享布局 v3）。

已通过完整 20Hz 周期、两种震动节奏、多手柄、重复按住、无后续输入仍停止、线程/API 失败、游戏震动恢复、快速切换、HTTP 保存与全部回归测试；已交叉编译和检查复制代码独立性，尚未实机验证震感。

## 0.3.3 每秒 40 次

网页增加每秒 40 次选项，按下和松开阶段各 12500 微秒。默认启动速度仍为每秒 10 次。已测试完整一秒的 40 次按下/松开周期和 HTTP 保存/读取；游戏实际触发频率仍受输入采样与技能机制限制。

## 0.3.2 每次启动恢复默认

按用户要求，服务取得单实例锁且通过启动检查后，原子替换旧设置，每次启动均清空连发选键、恢复每秒 10 次与默认快捷键（仅 L1+R1+十字键↓）。网页“允许连发”默认开启，但没有选键，因此不会连发。刷新网页与本次运行中更换游戏会保留当前设置；重新启动插件才清空。损坏的旧配置也会被重建。被旧实例锁阻止的重复启动不会改动正在运行实例的配置。此改动不解决网页服务未监听端口的问题。

## 0.3.1 启动与网页排查

修复残留 STOP 导致新实例在启动网页前静默退出的问题。明确启动 ELF 时会清除残留标记并继续运行；运行中的服务仍响应新建 STOP 正常退出。新增 `/data/ps5-turbo/startup.txt`，记录最近一次启动的版本、PID 与结果；旧实例锁、进程访问、kstuff、配置创建和网页打开失败均有原因。网页启动失败保留具体阶段和系统错误号。此文件是最近启动结果，不是实时健康监测。

若网页打不开，先保留并检查 `startup.txt` 与 `log.txt`，确认实际运行版本、网页是否成功监听以及是否有 STOP 退出记录。已通过残留 STOP、旧实例锁、kstuff/进程访问失败、真实端口冲突与原有回归测试，尚待主机验证。

## 0.3.0 兼容扩展

新增 CUSA（PS4）自动识别，保留 PPSA（PS5）；增加常见模拟器进程名识别与自定义应用编号清单。输入接口扩展到 `scePadReadExt`，并按单字节读取 PS4 的连接标志，避免填充字节影响断连判断。网页显示应用编号或模拟器进程名。

覆盖目标是 RetroArch、PS1/PS2、PSP、FBNeo、NS 模拟器所使用的标准 libScePad 读取路径，**不是已证实所有模拟器或所有游戏都可用**。具体识别规则和测试矩阵见 [COMPATIBILITY.md](COMPATIBILITY.md)。

## 0.2.6 网页可选快捷开关

新增两组独立勾选项，支持任意一个、两个都选或全部关闭。选项保存至现有配置，重启保留；旧配置未包含 `shortcuts` 时默认仅启用十字键组合。共享内存布局升级为 v2，升级前须关闭游戏并停止旧插件。已通过逻辑、HTTP、持久化、浏览器保存/刷新与交叉编译验证，尚待主机实测。

## 0.2.5 十字键组合开关

按用户选择改为 L1+R1+十字键↓（下方向），立即切换，持续按住只切换一次。移除 L3+R3 的长按检测。已覆盖组合键、持续按住、重复采样、多手柄、单键和不完整组合，以及 L3+R3 持续超过两秒仍不切换的回归测试；尚待主机验证。

## 0.2.4 长按快捷开关

按用户选择改为长按 L3+R3 两秒。短按不改变连发，所有 L3/R3 输入均保留给游戏；长按也可能触发游戏技能。按住只切换一次，释放任意一个摇杆键后才能再次长按切换。已测试两秒边界、短按、释放重置、持续按住、多手柄、断连和系统拦截；尚待主机验证。

## 0.2.3 新手柄快捷开关

使用 L1+R1+按下触摸板暂停/恢复当前手柄的连发，保留 L3+R3 给游戏原有操作。网页总开关继续优先。已覆盖持续按住、重复采样、多手柄独立状态、L3+R3 不被拦截和网页总开关优先的逻辑测试，尚待主机验证。

## 0.2.2 游戏组合键兼容

取消 L3+R3 连发快捷键，保留游戏的组合键操作。网页开关、选键与速度设置继续可用。已增加组合键在连发按下/松开阶段及单独 L3/R3 的回归测试，尚待主机验证。

## 0.2.1 切换游戏修复

实机日志显示，换游戏时旧进程可能仍可见，但共享内存已经无法读取。
0.2.0 会因恢复失败退出整个服务，网页保存随后出现 `Failed to fetch`。
0.2.1 在恢复失败或心跳失败后保留网页与配置保存，暂停挂接，等待旧进程退出后再检测新游戏；若一直等待，请完全关闭旧游戏。
同时修复卸载路径释放内存后继续读取的问题。
已通过模拟退出竞争的服务循环测试、内存检测和交叉编译，尚待主机验证换游戏恢复。

## 升级与使用

1. 保存进度并关闭游戏。
2. 将 `ps5-turbo-v0.4.2.elf` 导入 Payload Manager，选择同一插件条目的“替换”并启动新版。
   新版会自动请求旧服务退出并接替，无需手动创建 STOP。正常更新无需重启 PS5。
   若旧版 15 秒内未退出，新版会停止接替并在 `startup.txt` 说明原因，不会强杀旧版。
   第一次从旧网页升级后手动刷新一次；后续版本切换时新网页会自动刷新。
3. 手机与 PS5 连接同一局域网，在手机浏览器地址栏输入：

   **`http://你的PS5局域网IP:6081`**

   例如主机 IP 是 `192.168.1.50`，地址就是 `http://192.168.1.50:6081`。
   使用主机网络设置或 Payload Manager 中显示的局域网 IP，不能填 `127.0.0.1`。
4. 勾选需要连发的按键，选择速度，保持“允许连发”开启，点击“保存并应用”。不勾选任何键时，全部按键保持普通输入。
5. 进入 PS5 游戏。页面出现“已连接游戏”后，按住选中的按键连发，松手即停；未选中的键保持普通输入。
   游戏内也能打开手机页面修改设置，保存后立即生效。
6. 在“手柄快捷开关”勾选需要的组合，点击“保存并应用”：
   - L1+R1+十字键↓：按一次暂停，再按一次恢复。完整组合会被拦截；不完整组合保持正常按键处理。
   - 长按 L3+R3 两秒：保持两秒切换，松开后才能再次切换；输入仍传给游戏，可能同时触发技能。
   两个可同时勾选，也可全部取消。未勾选的组合不会触发插件开关。玩《三国无双》建议取消 L3+R3。
   手柄快捷键恢复连发震两下，暂停连发震一下；震感取决于游戏模式和接口支持。更改勾选后会解除当前手柄的临时暂停。网页“允许连发”关闭时，快捷键不能强行开启。选择仅在本次插件运行内保留；下次启动恢复默认。

当前版本固定每秒 20 次；实际频率受游戏输入采样和自身机制限制，8 个键共用此速度。
保存时会写入主机；刷新页面、在本次运行内更换游戏会保留选键和速度，重启插件则恢复默认。

## 默认关闭与旧配置

新版改用 `/data/ps5-turbo/settings-v2.txt`，**不会继承旧版的默认 × 连发**。
旧的 `settings.txt` 留在原处作为备份，不参与新版配置。
每次插件成功启动时重建的配置为：

```ini
enabled=1
mask=0x0000
half_us=25000
shortcuts=1
```

`enabled=1` 表示允许已勾选的键连发；`mask=0` 表示一个键也没勾选，所以不会连发。
下次启动会清空自己保存的选键，并恢复上述固定速度和默认快捷键。

## 手动配置与排查

网页端口为 6081，不是 Payload Manager 的网页端口。如果页面打不开，查看 `/data/ps5-turbo/log.txt` 是否出现 `settings page` 或 `settings page unavailable`。
网页启动失败时，仍可用现有文件管理器修改配置文件，每秒重新读取一次。
文件必须有 `enabled`、`mask`、`half_us` 三项；缺失或非法内容会暂停连发。

| 按键 | mask |
|---|---|
| × / ○ / □ / △ | 0x4000 / 0x2000 / 0x8000 / 0x1000 |
| L1 / R1 | 0x400 / 0x800 |
| L2 / R2 | 0x100 / 0x200 |
| 全部关闭 / 八键全开 | 0x0000 / 0xFF00 |

多个键用按位或合并，例如 × 和 □ 为 `0xC000`。`half_us` 为每个按下/松开阶段的微秒数，当前固定为 `25000`，其他值会被拒绝。
`shortcuts=0` 关闭两组快捷键，`1` 仅十字键组合，`2` 仅长按 L3+R3，`3` 同时启用。旧配置缺少该项时按 `1` 处理。

`enabled=0` 暂停全部连发。建议通过网页保存，写文件采用临时文件加重命名方式。

如果连发无效，保留日志供排查，查看 `attached to PPSA...`、`reads`、`changed`、`attach failed`。
同一游戏不能同时叠加两版服务，也不要同时运行其他输入重映射 payload 测试。

## 停止与移除

在文件管理器中创建空文件 `/data/ps5-turbo/STOP`。服务发现后会停用连发、尝试恢复游戏的输入调用，并退出。
也可以通过已确认的进程 PID 发送 SIGTERM。不要仅凭 `payload.elf` 名称结束进程，其他 payload 也可能同名。
退出游戏后移除 ELF 即可；未注册自动加载。重启主机也会清除该服务。
若日志报告恢复失败，关闭该游戏；不要重复加载服务尝试覆盖。

## 范围与限制

- 自动识别 `eboot.bin` 的 PPSA/CUSA 应用和已列出的模拟器进程；其他自制应用须将真实编号加入 `/data/ps5-turbo/targets.txt`。多个候选时不注入，不修改 ShellUI。
- PPSA 过滤是识别规则，不能证明程序一定是零售游戏；自制程序也可能使用 PPSA 编号。
- 覆盖 `scePadReadState`、`scePadReadStateExt`、`scePadRead`、`scePadReadExt` 的可识别导入调用。
  其他接口、直接调用、延迟加载模块或特殊输入路径可能不生效；不宣称全游戏支持。
- PS4 与模拟器扩展目前为实验支持。直接操作 HID、使用私有输入接口、无法识别的采样布局或未检测到的进程不会因此自动兼容。系统菜单自身不被 hook；游戏失焦依赖系统返回的 intercept 标志，尚待实测。
- 多手柄分别保存连发状态，最多 8 个 handle；超出数量或并发竞争时原样放行。
- 不与 AnyPad、其他重映射/输入 hook 同时测试；输入链冲突尚未验证。
- 服务失去心跳时，stub 在一定读取次数后停止修改数据。它不是按实际秒数计时的故障恢复。
- 停止后暂留游戏内的代码映射，避免正在执行的线程访问被释放的代码；关闭游戏后由系统释放。
- 休眠、恢复、USB/蓝牙切换，以及 新版在 13.60 系统上的稳定性仍需实机验证。

## 编译与测试

使用官方 ps5-payload-dev SDK v0.42，下载包由 SHA-256 校验。
依赖 Python 3、Node.js 18+（网页脚本测试）、make 和支持 PS5/ELF 的 Clang、LLD。普通 macOS 环境可按 SDK 文档安装 LLVM，并配置 `LLVM_CONFIG`。

```sh
tools/setup-deps.sh
make test
make
```

产物：`payload/ps5-turbo-v0.4.2.elf`（发布用，保留文件名，Payload Manager 可识别版本）和 `payload/ps5-turbo.elf`（兼容文件名）。版本统一由 `payload/version.h` 管理。`make` 会检查复制进游戏的代码块没有外部重定位，且全部入口都处于复制范围内。
逻辑测试覆盖连发阶段、重复时间戳、松手、多手柄与多按键独立状态、开关、防失联、扳机模拟值、断连、系统拦截、恢复、API 错误与批量读取边界。
HTTP 测试覆盖真实 socket 的页面加载、默认关闭、八键保存/持久化、全部取消、拒绝无效请求和慢连接超时。
浏览器测试覆盖勾选 R1、保存、刷新保留以及全部取消。
这些电脑端测试不能证明新版主机端的 hook、网页网络或所有游戏适配成功。
